This page consolidates the numbered lecture materials for CS1101S: Programming Methodology. This document introduces the module, presented by Boyd Anderson on August 10, 2022, covering its objectives, history, and the fundamental elements of programming [source:cs1101s-lecture-lecture-l1-print-pdf#section-1, cs1101s-lecture-lecture-l1-print-pdf#section-2, cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-print-pdf#section-4, cs1101s-lecture-lecture-l1-print-pdf#section-5, cs1101s-lecture-lecture-l1-view-pdf#section-1, cs1101s-lecture-lecture-l1-view-pdf#section-2, cs1101s-lecture-lecture-l1-view-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-4, cs1101s-lecture-lecture-l1-view-pdf#section-5].

## What is CS1101S?

CS1101S: Programming Methodology is a module designed to help students:
*   Understand the structure and interpretation of computer programs [source:cs1101s-lecture-lecture-l1-print-pdf#section-1, cs1101s-lecture-lecture-l1-print-pdf#section-4, cs1101s-lecture-lecture-l1-view-pdf#section-1, cs1101s-lecture-lecture-l1-view-pdf#section-4].
*   Learn how to program [source:cs1101s-lecture-lecture-l1-print-pdf#section-4, cs1101s-lecture-lecture-l1-view-pdf#section-4].
*   Gain insights into various subject areas of computer science [source:cs1101s-lecture-lecture-l1-print-pdf#section-4, cs1101s-lecture-lecture-l1-view-pdf#section-4].
*   Develop an appreciation for how computer science "ticks" [source:cs1101s-lecture-lecture-l1-print-pdf#section-4, cs1101s-lecture-lecture-l1-view-pdf#section-4].
*   Ultimately, foster a love for computer science [source:cs1101s-lecture-lecture-l1-print-pdf#section-4, cs1101s-lecture-lecture-l1-view-pdf#section-4].

### Module History and Evolution

The core concept of this module originated at MIT in the 1980s, developed by Hal Abelson and Jerry Sussman. It is based on their seminal book, "Structure and Interpretation of Computer Programs" (SICP) [source:cs1101s-lecture-lecture-l1-print-pdf#section-1, cs1101s-lecture-lecture-l1-print-pdf#section-5, cs1101s-lecture-lecture-l1-view-pdf#section-1, cs1101s-lecture-lecture-l1-view-pdf#section-5].

The module was first introduced at DISCS (Department of Information Systems and Computer Science) in Semester 1, 1997/1998, under the name "IC1101S." Its inaugural lecturers were Jacob Katzenelson and Leong Tze Yun. In Semester 1, 1998/1999, Jacob Katzenelson renamed it to "CS1101S" [source:cs1101s-lecture-lecture-l1-print-pdf#section-1, cs1101s-lecture-lecture-l1-view-pdf#section-1].

More recently, Martin Henz took over the module in 2012, adapting SICP to use JavaScript instead of Scheme. He taught the module from 2012 to 2021 and is currently on sabbatical. Low Kok Lim joined the teaching team in 2014 [source:cs1101s-lecture-lecture-l1-print-pdf#section-1, cs1101s-lecture-lecture-l1-view-pdf#section-1].

### Module Overview

The module is structured into four main units:

*   **Unit 1: Functions** (Textbook Chapter 1) [source:cs1101s-lecture-lecture-l1-print-pdf#section-2, cs1101s-lecture-lecture-l1-view-pdf#section-2]

    *   Focuses on reading programs and using the substitution model.
    *   Includes example applications such as Runes and curves.
*   **Unit 2: Data** (Textbook Chapter 2) [source:cs1101s-lecture-lecture-l1-print-pdf#section-2, cs1101s-lecture-lecture-l1-view-pdf#section-2]
    *   Covers data structures like pairs, lists, and trees.
    *   Explores searching and sorting in lists and trees.
    *   Features an example application: sound processing.
*   **Unit 3: State** (Parts of Textbook Chapter 3) [source:cs1101s-lecture-lecture-l1-print-pdf#section-2, cs1101s-lecture-lecture-l1-view-pdf#section-2]
    *   Introduces programming with stateful abstractions.
    *   Covers arrays, loops, and searching/sorting arrays.
    *   Employs the environment model for reading programs.
    *   Includes example applications such as robotics and video processing.
*   **Unit 4: Beyond** (Parts of Textbook Chapters 3 and 4) [source:cs1101s-lecture-lecture-l1-print-pdf#section-2, cs1101s-lecture-lecture-l1-view-pdf#section-2]

    *   Explores computing with Register Machines, Logic Programming, and Concurrency.

## Elements of Programming

A powerful programming language provides three core elements [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3]:
1.  **Primitives:** The simplest elements.
2.  **Combination:** Ways to build compound elements from simpler ones.
3.  **Means of Abstraction:** Ways to name and manipulate compound elements as units.

### Processes and Programming

A **process** is defined as a set of interacting activities that produce a result, unfolding according to patterns that describe or prescribe it [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3]. Examples range from natural phenomena like galaxy formation and metabolic pathways to human systems like political parties and industrial production.

A **computational process** specifically refers to a set of activities within a computer designed to achieve a desired result [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3]. In programming, programs are used to prescribe how these computational processes unfold [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].

As computer systems become more complex, effective **communication** among architects, designers, programmers, operators, and users becomes crucial. Programs, by prescribing computational processes, play a central role in this human communication during system construction and operation. Thus, programming is fundamentally about communicating computational processes [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].

### Primitive Expressions (1.1.1)

Primitive expressions are the simplest building blocks in a programming language [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Numerals:** Represent numbers using decimal notation, e.g., `0`, `-42`, `486`. The interpreter can evaluate numerals, yielding the numbers they represent [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Expressions vs. Programs in Source:** In Source, expressions are not complete programs. They must be terminated with a semicolon to become a program. For example, `486;` is a program [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].

### Operator Combinations (1.1.1)

Operators are a means of combination, allowing the creation of complex expressions from simpler ones [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Notation:** Standard infix notation is used, where the operator is placed between its operands, respecting usual mathematical precedences. Examples include `5 * 99;` and `25 - (4 + 2) * 3;` [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   The lecture would typically include a demonstration of expression evaluation.

### Naming Abstraction (1.1.2)

Naming provides a means of abstraction, allowing values to be associated with names [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Environment:** The JavaScript interpreter maintains an environment (a table) that stores associations between names and their corresponding values [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Constant Declarations:** The `const` keyword is used to add a name-value entry to this environment table. Example: `const size = 2;` allows `5 * size;` to evaluate to `10` [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Pre-declared Names:** Source provides several pre-declared constants and functions.
    *   **Pre-declared constants:** For instance, `math_PI` refers to the constant $\pi$ [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
    *   **Pre-declared functions:** Operators like `+` are functions. `math_sqrt` is an example of a pre-declared function for square roots [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Function Application Expressions:** Functions are applied by enclosing their arguments in parentheses, similar to mathematical notation. Example: `math_sqrt(15);` applies the square root function to `15` [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].

### Functional Abstraction (1.1.4)

Compound functions offer a more advanced means of abstraction, allowing for reusable blocks of code [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Function Declaration:** A `function` declaration assigns a function to a name. For example:
    ```javascript
    function square(x) {
        return x * x;
    }
    ```
    This declares `square` as a function that takes an argument `x` and returns `x` multiplied by itself [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Function Application:** Once declared, these functions can be applied by supplying arguments in parentheses, just like pre-declared functions.
    *   `square(14);` evaluates to `196`.
    *   `square(21);` evaluates to `441`.
    *   `square(2 + 5);` evaluates to `49`.
    *   `square(square(3));` evaluates to `81` [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].

### Predicates and Conditional Expressions (1.1.6)

These elements enable programs to make decisions and control flow [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Boolean Values:** `true` and `false` are the two boolean values, representing answers to yes/no questions [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Predicates:** A predicate is a function or expression that returns or evaluates to a boolean value.
    *   Examples: `true;`, `false;`, `x >= 1;` [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
    *   A function `adult(x)` returning `x >= 18;` is also a predicate [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
*   **Conditional Expressions:** These allow a program to check a condition (a yes/no question) and return a different value based on the answer [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
    *   Example: `adult(my_age) ? enter_club() : go_to_movie()` means if `adult(my_age)` is true, `enter_club()` is executed; otherwise, `go_to_movie()` is executed [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
    *   This is useful for implementing functions like `abs(x)`, where the result depends on whether `x` is greater than or equal to 0 [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].

The lecture concludes by welcoming students to Source Academy and encouraging them to start with their first Path, "Elements of Programming" [source:cs1101s-lecture-lecture-l1-print-pdf#section-3, cs1101s-lecture-lecture-l1-view-pdf#section-3].
